## 1. PLAN.md 대비 개선 사항

| # | 계획 | 변경 | 이유 |

| 8 | 베스트도 흐린 그룹 | **"전체가 흐림" 경고 배지** | 연사 전체가 흔들린 경우 베스트만 남겨도 흐린 사진이 남는다. |
| 9 | 삭제 후 남은 후보 처리 없음 | 선택이 없을 때 주요 행동이 **"남은 n장 모두 유지"**로 바뀜 | 검토 대기 0건으로 끝나는 완료감. 다시 볼 필요 없는 사진이 계속 남지 않게. |
| 10 | 하단 "선택한 n개 삭제" | **"n장 삭제 · 1.2GB 확보"** | 정리의 목적(용량)을 바로 보여준다. |
| 11 | 카드 원본 삭제는 항상 | 설정 + 가져오기 화면에서 **이동/복사 선택** (기본 이동) | 카드를 백업으로 남기고 싶은 날도 있다. |
| 12 | — | **비정상 종료 기록 + 다음 실행 때 표시(복사 가능)** | 기기에서 직접 디버깅할 수 없어 오류 내용을 받을 통로가 필요하다. |
| 13 | 자동 업데이트(이후 버전) | **v0.1부터 포함**: 매니페스트 확인 → 앱이 직접 다운로드·SHA-256 검증 → PackageInstaller 설치 | 사용자 요청. 기기 테스트가 어려운 만큼 수정본을 빨리 받는 통로가 먼저 있어야 한다. |
| 14 | 정렬 키 SubSec 없으면 파일 번호 | 같음 + **파일 번호 순서로 동률 해소** | 1초 안 여러 장의 SubSec이 같을 수 있다. |

## 3. 카드 감지와 가져오기

### 3.1 카드 감지 (`storage`)
- `StorageManager.getStorageVolumes()` 중 `isRemovable && state == MOUNTED`인 볼륨. `volume.directory`(API 30+)로 루트 경로.
- 카메라 카드 판정: 루트에 `DCIM/` 폴더가 있고 그 아래(재귀)에 대상 확장자 파일이 1개 이상.
- 접근 판정: `File(root).listFiles() != null`이면 DIRECT. 아니면 저장된 SAF 권한(볼륨 UUID 키, `takePersistableUriPermission`)이 있으면 SAF, 없으면 `CardState.NeedsAccess`.
  - SAF 승인: `StorageVolume.createOpenDocumentTreeIntent()` (해당 볼륨 루트가 미리 선택됨).
- 실시간 갱신: `StorageManager.registerStorageVolumeCallback` + `refresh()`(화면 복귀 시). 권한이 없으면 `NoPermission`.
- `MediaMountedReceiver`: `MEDIA_MOUNTED` 수신 → `goAsync()`로 빠르게 카메라 카드인지 확인(최대 수 초) → 알림 "카메라 카드가 연결됨 · 사진 n · 영상 m" + 액션 [가져오기](ImportService 직접 시작) + 탭 시 가져오기 화면. 설정에서 카드 알림을 끄면 띄우지 않는다. `MEDIA_EJECT/UNMOUNTED/REMOVED/BAD_REMOVAL` → 카드 알림 제거, 모니터 갱신.

### 3.2 스캔 (`importer`)
- 대상: `DCIM/**` 재귀, 확장자 `JPG JPEG HIF HEIF CR3 MP4 MOV`(대소문자 무시). 숨김 파일(`.`으로 시작)·그 외 확장자는 건드리지 않는다.
- 촬영 단위: 같은 폴더 + 같은 기본 이름(확장자 제외). 대표 파일 우선순위 JPG/JPEG > HIF/HEIF > CR3. 영상은 각자 단위.
- 이전 기록 대조: `MediaDao.importedKeys(volumeId)`의 (상대 경로, 크기, 수정 시각)과 같으면 "이미 가져온 파일"(복사 생략, 이동 모드면 카드 원본만 삭제).
- 여유 공간: `StatFs(primaryRoot).availableBytes ≥ 새 파일 용량 + 2GB`가 아니면 시작 불가(부족 용량 표시).
- 결과: `CardScanSummary`.

### 3.3 파일 처리 순서 (`ImportEngine`, 파일 1개 기준)
1. 저장 위치 결정: `StoragePaths.destDir(폴더, 월별 여부, 촬영 시각)`. 촬영 시각은 사진이면 카드 파일 EXIF(헤더만 읽음), 실패 시 파일 수정 시각.
2. 이름 결정(촬영 단위 전체에 같은 접미사): 접미사 "", "_1", "_2"… 순서로, 단위의 모든 파일 이름이 비어 있으면 사용. 기존 파일이 있으면 크기 비교 → 같으면 해시 비교 → 같으면 그 파일은 **중복**(복사 생략), 다르면 다음 접미사.
3. `이름.photocull.part`로 복사하며 SHA-256 계산(카드는 한 번만 읽음, 버퍼 1MB), `fd.sync()`.
4. `.part`를 다시 읽어 해시 비교. 불일치면 `.part` 삭제 후 1회 재시도, 그래도 불일치면 FAILED(카드 원본 유지).
5. `.part` → 최종 이름, `setLastModified(원본 수정 시각)`, DB `VERIFIED`.
6. 이동 모드면 카드 원본 삭제 → `SOURCE_DELETED`, 실패하면 `SOURCE_DELETE_FAILED`(복사본 유지).
7. 미디어 스캔(`MediaScannerConnection.scanFile`)은 20개마다 + 끝날 때 묶어서.
8. 사진 대표 파일이 검증되면 `AnalysisController.kick()`.

예외:
- 카드 분리(읽기 IOException + 볼륨이 더 이상 MOUNTED가 아님): 현재 `.part` 삭제, 세션 INTERRUPTED, `ImportError.CardRemoved`. 다시 연결하면 남은 파일만 대상이 된다(이미 옮긴 파일은 카드에 없거나 기록과 일치).
- 시작할 때와 앱 시작 시 저장 폴더의 `*.photocull.part` 정리.
- 취소: 현재 파일의 `.part` 정리 후 중단. 이미 옮긴 파일은 유지, 나머지는 카드에 그대로.

### 3.4 실행 (`ImportService`)
- 포그라운드 서비스 `dataSync`. 시작 즉시 `startForeground`(진행 알림: 제목 "사진 가져오는 중", 내용 "120/324 · 45% · 약 3분 남음", 진행 바, [취소] 액션).
- 가져오는 동안 부분 wake lock(타임아웃 있는 `acquire`).
- 끝나면 분석이 끝날 때까지 서비스를 유지("분석 중 n/m"), 그 뒤 결과 알림 "가져오기 완료 · 324개 이동 · 흐림 12장, 연사 8그룹" (탭 → 검토) 후 `stopSelf`.
- 상태는 `ImportControllerImpl.state`(StateFlow)로 화면과 공유한다(같은 프로세스).

## 4. 분석

### 4.1 사진 1장 (`ImageAnalyzer`)
- 디코드: `BitmapFactory`, `inSampleSize` = 긴 변이 3000px 이상 유지되는 가장 큰 2의 거듭제곱(6000px → 2). `ARGB_8888`. 실패하면(HIF 등) `ImageDecoder`로 재시도, 그래도 실패면 `analysisFailed = true`.
- 그레이스케일: `Y = (77R + 150G + 29B) >> 8`, 행 단위 `getPixels`로 변환해 비트맵은 바로 해제.
- EXIF(`androidx.exifinterface`): 촬영 시각(`dateTimeOriginal`, SubSec 포함), ISO, 셔터, 조리개, 초점거리, 회전. 너비·높이는 원본 기준(회전 반영).
- 동시 2장까지(메모리 ~30MB/장).

### 4.2 선명도 (`Sharpness`, 순수 Kotlin·JVM 테스트 가능)
- 3×3 Laplacian `[0,1,0; 1,-4,1; 0,1,0]` 응답의 분산을 타일별로 계산. 가로 사진 6×4, 세로 사진 4×6.
- 점수 = 상위 3개 타일 분산의 평균. 초점 위치 = 최고 타일 중심(0..1, 회전 반영한 표시 좌표).

### 4.3 흐림 기준 (`BlurThresholds`)
- 단독 사진: 점수 < 임계값(민감도 낮음 40 / 보통 150 / 높음 400)이면 흐림 후보.
  - Canon EOS R10 실사진 19장 + 인공 흐림(가우시안 σ1·2·4, 모션 5·15px, 잡음)으로 보정. 보통 150은 σ2 흐림의 13/19를 잡고 원본은 0/19. 근거 표는 `analysis/BlurThresholds.kt`.
  - 한계: 장면별 점수 차이가 40배라 절대값만으로는 완벽하지 않다(연사 그룹 안 상대 비교가 더 정확). 한 방향 모션 블러와 강한 잡음은 점수를 덜 낮춘다. 실제 R10 원본으로 재보정 예정(테스트 `CalibrationHarnessTest`, `PHOTOCULL_CALIB_DIR`).
- 그룹 안: 그룹 최고 점수의 60% 미만이면 "흐림" 배지.

### 4.4 dHash·그룹 (`DHash`, `Grouping`, 순수 Kotlin)
- dHash 64bit: 그레이 9×8 영역 평균 축소 → 행마다 왼쪽 > 오른쪽 비트.
- 정렬: 촬영 시각, 같으면 카드 상대 경로(파일 번호).
- 앞 사진과 간격 ≤ 연사 간격(기본 1.0초) → 같은 그룹(연사 연결). 아니면 간격 ≤ 10초이고 해밍 거리 ≤ 10 → 같은 그룹(유사 연결).
- 그룹 종류: 연사 연결이 하나라도 있으면 BURST, 아니면 SIMILAR. 2장 이상만 저장.
- 베스트 = 최고 점수. 단, 이전 그룹의 고정 베스트(`bestPinned`)가 새 그룹에 있으면 유지.
- 대상: 대표 사진 중 PENDING/KEPT. 분석 중에는 최대 5초마다, 분석이 끝나면 즉시, 설정 변경 시 다시 계산한다. 계산은 트랜잭션 밖에서 하고 바뀐 행만 쓴다(`Grouping.diff` → `GroupingDao.applyDiff`). 쓰는 순간 고정 베스트를 다시 읽어 그사이의 사용자 지정을 잃지 않는다.

### 4.5 영상
- `MediaMetadataRetriever`로 길이·해상도·촬영 시각. 흐림 판정 없음. ≤ 3초는 "실수 촬영 후보".

## 5. 화면

공통: 하단 탭 4개 홈 / 검토 / 휴지통 / 설정 (접힘 = 하단 바, 펼침 = 레일). 가져오기·그룹 상세·온보딩은 탭 없는 흐름 화면. 검토 탭 배지 = 검토 대기 건수.

### 5.1 홈 — 주요 행동: 카드 있으면 "가져오기", 없으면 "검토 계속"
- 카드 상태 카드(가장 위, 가장 크게): 미연결("카드 리더를 연결하세요" + 안내) / 카메라 카드(라벨, 사진·영상 수, 용량, 이미 가져온 수) / 카메라 카드 아님 / 폴더 승인 필요([승인]) / 권한 없음([권한 허용]) / 가져오는 중(진행률, 탭 → 가져오기 화면).
- 검토 대기: 흐림 n · 연사 n그룹 · 영상 n — 각 항목 탭 → 해당 탭.
- 분석 중이면 "분석 중 120/324" 진행 표시.
- 마지막 가져오기 요약(날짜, 이동 수, 실패·카드 삭제 실패가 있으면 경고 줄).
- 업데이트가 있으면 상단 앱 바에 "업데이트" 칩 → 업데이트 시트.

### 5.2 가져오기 — 주요 행동: "가져오기 시작"
- 스캔 중: 스피너 + "카드 확인 중".
- 준비: 사진/RAW/영상 수, 총 용량, 촬영 기간, 이미 가져온 n개(건너뜀), 저장 위치, 폰 여유 공간 막대(필요 vs 여유). "카드 원본" 선택(이동 후 삭제 / 카드에 남김). 하단 [가져오기 시작 · 324개 · 18.4GB]. 공간 부족이면 비활성 + 부족 용량 + [저장공간 설정].
- 진행: 큰 진행 바 + %, "120 / 324개", "1.2 / 18.4GB", 속도, 남은 시간, 현재 파일명. 분석 진행 보조 표시. [취소](외곽선 버튼, 주요 버튼과 떨어진 위치). 화면을 나가도 계속된다는 안내.
- 결과: 이동 n(성공) / 중복 건너뜀 n / 실패 n(펼치면 파일별 이유) / 카드에서 못 지움 n(쓰기 금지 스위치 확인 안내). "카드를 뽑기 전에 알림창에서 USB 저장소를 '꺼내기' 하세요" + [저장공간 설정]. 주요 행동 [검토 시작 · 흐림 12 · 연사 8그룹](분석 중이어도 활성).
- 오류: 카드 분리(이어서 가져오기 안내 + [다시 시도]), 권한 없음, 카드 없음.

### 5.3 검토 — 탭 3개 흐림 / 연사 / 영상, 주요 행동: "n장 삭제 · 용량 확보"
- **흐림 탭**: 상단에 민감도 세그먼트 버튼(낮음/보통/높음, 바꾸면 즉시 목록 변경) + 모두 선택/해제. 선명도 낮은 순 그리드(칸 최소 112dp), 칸마다 "선명도 n" 라벨, 오른쪽 위 선택 체크(48dp). 기본 미선택.
  - 사진 탭 → 뷰어(가장 선명한 위치 100% 확대), 뷰어 하단 [삭제 대상으로 표시/해제] 토글.
  - 펼침 화면: 왼쪽 그리드 + 오른쪽 미리보기(선택한 칸, 100% 확대).
- **연사 탭**: 그룹 카드 목록(베스트 썸네일 + "연사 12장"/"비슷한 사진 3장" + 시각 + 용량 + 흐림 배지). 상단 [모든 그룹에서 베스트만 남기기 (n장 삭제)]. 카드 탭 → 그룹 화면.
- **그룹 화면**(route): 큰 확대 뷰어(같은 위치 비교) + 필름스트립(접힘: 아래 가로, 펼침: 오른쪽 세로 그리드). 베스트 배지(별 아이콘 + "베스트"), 상대 흐림 배지. 각 장 선택 체크, 기본 = 베스트 외 전부. [베스트로 지정] 보조 버튼. 하단 [n장 삭제 · 용량](삭제 후 나머지는 '남기기', 그룹 완료 → 뒤로).
- **영상 탭**: 위쪽 "실수 촬영 후보(3초 이하)" 섹션, 아래 나머지(용량 큰 순). 칸에 길이·용량 라벨. 탭 → 재생. 기본 미선택.
- 삭제 후 스낵바 "n장을 휴지통으로 옮겼습니다 · [실행 취소]".
- 선택이 없을 때 하단 주요 행동 = [남은 n장 모두 유지](톤 버튼). 비어 있으면 Empty("흐린 사진이 없습니다" + 다음 탭으로 이동 버튼).

### 5.4 뷰어 (`ui/viewer/PhotoViewer`, 검토·그룹·휴지통이 오버레이로 사용)
- 검은 배경, 좌우 넘기기(HorizontalPager), 핀치/더블탭 확대, 큰 사진은 영역 디코딩(telephoto `ZoomableAsyncImage`).
- `startAtFocus`: 열 때 focusX/focusY 위치를 원본 100%로 확대. [전체 보기 ↔ 100%] 토글 버튼.
- 상단: 뒤로, 파일명, "3 / 12", EXIF 한 줄(ISO · 셔터 · 조리개 · 초점거리), 선명도.
- 영상: VideoView 재생/일시정지, [다른 앱으로 열기].
- 하단: 호출 측이 넘긴 `bottomBar`.

### 5.5 휴지통 — 주요 행동: "선택한 n개 복원"
- 그리드, 칸마다 "n일 남음". 탭 → 뷰어(복원 버튼). 선택 체크.
- 하단: [n개 복원](주요). 영구 삭제는 상단 앱 바 메뉴(휴지통 비우기 / 선택 영구 삭제) → 확인 대화상자(대상 수·확보 용량·되돌릴 수 없음, 버튼 "n개 영구 삭제" / "취소", 기본 포커스 취소).
- Empty: "휴지통이 비어 있습니다 · 삭제한 사진은 30일 동안 여기에 보관됩니다".

### 5.6 설정
- 가져오기: 저장 폴더(DCIM/아래 이름, 편집 대화상자), 월별 하위 폴더, 카드 원본(이동/복사), 카드 연결 알림.
- 검토: 흐림 민감도, 연사 간격(0.5/1/2초), 짧은 영상 기준(3초).
- 휴지통: 보관 기간(7일/30일/무기한).
- 화면: 테마(시스템/라이트/다크).
- 권한: 모든 파일 접근, 알림, 앱 설치(업데이트용) — 각각 상태(아이콘+텍스트) + [설정 열기].
- 앱 정보: 버전·채널·커밋, 자동 업데이트 확인 스위치, [업데이트 확인], 릴리스 페이지, 오류 보고서(마지막 비정상 종료 내용 보기·복사·지우기).

### 5.7 시작(온보딩) — 주요 행동: "계속"
- "시작하기 전에" + 단계 목록: ① 모든 파일 접근(필수, 이유) [허용하러 가기] ② 알림(권장) [허용]. 허용되면 체크 표시(화면 복귀 시 재확인). 필수 권한이 있어야 [계속] 활성.

## 6. 자동 업데이트

- 확인 순서: ① `https://github.com/Leepy0/PhotoCull/releases/latest/download/PhotoCull.json` ② `https://api.github.com/repos/Leepy0/PhotoCull/releases/latest`(자산 목록에서 apk·json 찾기). 404/릴리스 없음 = 최신.
- 매니페스트: `{ "version":"0.2.0", "versionCode":200, "file":"PhotoCull.apk", "url":"…/releases/download/v0.2.0/PhotoCull.apk", "sha256":"<hex>", "size":123, "published":"…", "page":"…/releases/tag/v0.2.0", "notes":"…" }`
- 주기: 앱 시작 3초 뒤(마지막 확인 후 6시간 지났을 때), WorkManager 하루 1회(네트워크 연결 시) → 새 버전이면 알림. 설정에서 끔. 수동 [업데이트 확인]은 항상.
- 받기: `cacheDir/update/PhotoCull-<ver>.apk.partial` → SHA-256 일치 시 이름 변경. 불일치/중단 시 삭제.
- 설치: `PackageInstaller` 세션, `setRequireUserAction(USER_ACTION_NOT_REQUIRED)`(권한 `UPDATE_PACKAGES_WITHOUT_USER_ACTION`). `STATUS_PENDING_USER_ACTION`이면 시스템 확인 화면을 띄운다. '출처를 알 수 없는 앱' 허용이 없으면 먼저 그 설정으로 안내.
- 가져오는 중에는 설치하지 않는다(완료 후 설치 안내).
- 설치 후 첫 실행: "v0.2.0으로 업데이트됨" + 변경 내용 1회 표시.
- 서명: 저장소 밖 키(GitHub Secrets). 디버그 키 빌드(`BUILD_CHANNEL=local`)는 업데이트 확인은 하되 설치 시 서명 불일치 가능성을 안내.
- 릴리스는 기본 브랜치(main)에서만 만든다(작업 브랜치의 테스트 빌드가 최신 릴리스가 되지 않게). 조건: 서명 Secrets 있음 + `vX.Y.Z` 태그 없음 + 기존 최신 태그보다 높은 버전.
